# ysp-live-go

Go 服务，为央视频直播频道生成 M3U/HLS 播放列表，并提供部分春晚点播入口。直播播放列表使用央视频 CDN 分片地址；春晚点播请求解析播放地址后重定向至 CDN。

## 要求

- Go 1.22 或更高版本

## 构建

在项目根目录执行：

```bash
go build -o ysp-live-go ./cmd/ysp-live
```

交叉编译 Linux ARM64：

```bash
mkdir -p dist
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o dist/ysp-live-linux-arm64 ./cmd/ysp-live
```

## 运行

默认监听 `127.0.0.1:8767`：

```bash
./ysp-live-go
```

播放器订阅地址：

```text
http://127.0.0.1:8767/all.m3u
```

在局域网提供服务时，显式绑定所有网络接口：

```bash
./ysp-live-go -bind 0.0.0.0 -port 8767
```

服务没有用户认证。绑定 `0.0.0.0` 时，请通过防火墙限制访问范围，不要直接暴露到公网。

## HTTP 路由

| 路径 | 用途 |
| --- | --- |
| `/` | 频道列表 |
| `/all.m3u` | 包含直播和春晚点播的分组 M3U 列表 |
| `/health` | 健康检查 |
| `/diag` | 频道状态 |
| `/<slug>.m3u8` | 单频道播放列表 |
| `/vod/spring-gala/<slug>.mp4` | 春晚点播入口 |
| `/vod/2023-spring-festival.mp4` | 兼容旧版 2023 春晚订阅 |

春晚列表按年份升序收录 2020、2022、2023、2024 和 2026 年的完整晚会。

## 缓存与长期运行

频道空闲 120 秒后停止刷新，再次访问时会检查缓存时效。过期或首次加载时，
同一频道的并发请求共用一次后台刷新，并等待结果；客户端断开不会取消其他
观众需要的刷新。服务退出会取消上游请求并等待后台任务结束。

普通频道缓存最多保留 30 秒；BK 模式还会按上游目标分片时长收紧时效。
刷新失败时仅允许短时间使用仍在有效期内的缓存，过期后返回 `503` 和
`Retry-After`，不再用 `200` 返回陈旧列表。连续三次失败后每 30 秒重试；
恢复后自动回到正常刷新频率。即使上游持续返回 `200`，分片超过 30 秒没有
前进也会标记为异常。这个阈值针对当前短分片直播源，不适用于长分片点播。

`/diag` 显示每个频道的最后成功时间、分片更新时间、`worker`（是否有后台
刷新任务）、`fresh`（缓存是否仍有效）和最近错误。`/health` 仅检查进程能否
响应，不代表所有频道或客户端直连的 CDN 分片都可播放。

长期运行的资源边界：每个频道最多一个刷新任务；JCE 分片缓存最多 60 个；
外部 4K 后端新写入日志按 10 MiB 轮转，保留三个历史文件。主程序日志写到
标准错误，部署时应交给带容量限制的 systemd journal、容器日志驱动或
logrotate 管理，避免把输出无限追加到单个文件。第三方 4K 后端自身的内存、
设备状态和缓存文件不受本项目控制。

上游鉴权、CDN 地址和协议可能变化，客户端也可能无法访问分片；这些不能由
本地缓存修复保证。故障时保留 `/diag`、对应时间的日志以及播放器报错，
区分列表获取失败与客户端直连 CDN 失败。

## 首播、切台与码率

BK 取流会优先复用上次成功的 CDN。首选源超过 250 毫秒尚未完成时，开始探测
一个备用源；单频道最多同时拉取两个候选源，选出有效列表后取消并回收其他请求。
网络失败、列表停滞和竞争中明显较慢的地址冷却 10 秒。候选源及其健康记录最多
保留 16 个，签名地址更新时清理旧记录，避免长时间运行后累积。

仍能成功获取列表的缓存地址会继续使用，不再每隔五分钟先阻塞查询新地址。
缓存地址全部失败时才重新发现；新签名可以立即尝试，但不会清除已有的分片
停滞历史。切回缓存仍有效的频道直接返回列表，不等待上游请求。

对于上游返回的多码率列表，默认选择峰值带宽不超过 **6 Mbps** 的最高码率版本；
如果全部超过上限，选择最低码率版本。选择与列表顺序无关。可调整上限，例如：

```bash
./ysp-live-go -max-bandwidth 3000000
```

`-max-bandwidth 0` 选择最高码率。这是服务端固定选档策略，不是播放器自适应码率；
只对具有多个版本的 BK 播放列表生效，不会转码或限制单码率流的实际下载速度，
也不会改变独立 4K 后端的选档。

JCE 播放列表会保留上游的时间线切换标记，并在窗口滑动、标记移出窗口及重复
刷新时保持分片的 discontinuity sequence 稳定。

## 验证

```bash
go test -race ./...
go vet ./...
```

回归测试包含半年旧缓存重新打开、并发请求合并、客户端取消、上游失败与恢复、
停滞源切换、慢源探测与取消、首播和切台、签名续期、带宽选档、时间线标记随
窗口滑动、后台任务退出、分片窗口重复更新、日志轮转和 JCE 异常数据。
这是状态与故障模拟，不等同于实际运行半年。

可选的 Postman 本地 HTTP 模拟见
`postman/simulations/hls-recovery.context.md`，验证服务经过真实 HTTP 请求走完
正常播放列表、上游 503、恢复的路径，不访问真实央视频服务。

## 可选 4K 后端

4K 后端默认禁用。启用自动发现：

```bash
./ysp-live-go -backend auto
```

或指定后端二进制的绝对路径：

```bash
./ysp-live-go -backend /path/to/ysptp-project-arm64
```

后端默认使用 `8766` 端口，可通过 `-backend-port` 修改。该后端是独立的外部二进制，不包含在本项目中；启用前请自行确认其来源和行为。

## Google App Engine Standard

`app.yaml` 部署到 App Engine `default` 服务，使用 Go 1.27、F1 实例，允许缩容到零并限制最多一个实例。App Engine Standard 不支持本地 4K 子进程，因此部署时保持 4K 后端禁用。

除 `/health` 外的路由需要 `token` 查询参数。配置中只保存 token 的 SHA-256 摘要，不保存原文。更换 token 时生成新值并更新 `app.yaml` 中的 `YSP_ACCESS_TOKEN_SHA256`：

```bash
TOKEN="$(openssl rand -hex 32)"
printf '%s' "$TOKEN" | shasum -a 256
```

部署前还需要将 `YSP_PUBLIC_BASE_URL` 设为实际对外 HTTPS 地址，然后执行：

```bash
gcloud app deploy app.yaml --project PROJECT_ID
```

播放器聚合订阅地址为：

```text
https://YOUR_HOST/all.m3u?token=YOUR_TOKEN
```
