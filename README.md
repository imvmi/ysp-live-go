# ysp-live-go

Go 服务，为央视频直播频道生成 M3U/HLS 播放列表，并提供部分春晚点播入口。直播播放列表使用央视频 CDN 分片地址；春晚点播请求解析播放地址后重定向至 CDN。

## 要求

- Go 1.22 或更高版本
- 内置设备协议不需要 Python 或额外二进制

## 构建

在项目根目录执行：

```bash
go build -o ysp-live-go ./cmd/ysp-live
```

交叉编译 Linux ARM64：

```bash
mkdir -p dist
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o dist/ysp-live-linux-arm64 ./cmd/ysp-live
```

## 运行

默认监听 `127.0.0.1:8767`：

```bash
./ysp-live-go
```

内置设备协议默认启用。频道先尝试 BK/JCE；只要其中有仍有效的播放列表，
就直接返回，不再后台预热或获取设备高清源。只有 BK/JCE 都没有有效列表时，
CCTV10 等支持设备协议的频道才尝试设备备用源，并按需生成和持久化模拟电视身份。
无需任何外部组件或额外参数，设备会话、频道地址和播放列表会复用。
默认状态文件为程序所在目录下的 `data/device-state-go.json`。也可以显式指定：

```bash
./ysp-live-go -data-dir /var/lib/ysp-live-go
```

如只想使用 BK/JCE，可传入 `-device=false`。

播放器订阅地址：

```text
http://127.0.0.1:8767/all.m3u
```

在局域网提供服务时，显式绑定所有网络接口：

```bash
./ysp-live-go -bind 0.0.0.0 -port 8767
```

服务没有用户认证。绑定 `0.0.0.0` 时，请通过防火墙限制访问范围，不要直接暴露到公网。

## HTTP 路由

| 路径 | 用途 |
| --- | --- |
| `/` | 频道列表 |
| `/all.m3u` | 包含直播和春晚点播的分组 M3U 列表 |
| `/health` | 健康检查 |
| `/diag` | 频道状态 |
| `/<slug>.m3u8` | 单频道播放列表 |
| `/_device/media/*` | 内置设备协议的签名媒体中继（供播放列表内部使用） |
| `/vod/spring-gala/<slug>.mp4` | 春晚点播入口 |
| `/vod/2023-spring-festival.mp4` | 兼容旧版 2023 春晚订阅 |

春晚列表按年份升序收录 2020、2022、2023、2024 和 2026 年的完整晚会。

## 缓存与长期运行

频道空闲 30 秒后停止刷新，再次访问时会检查缓存时效。过期或首次加载时，
同一频道的并发请求共用一次后台刷新，并等待结果；客户端断开不会取消其他
观众需要的刷新。服务退出会取消上游请求并等待后台任务结束。

设备备用源同样按频道合并刷新，单次共享刷新最多 20 秒；单个观众取消或等待
超时不会计入频道故障。控制接口排队支持取消，退出时会等待设备刷新、心跳和
媒体中继结束。设备列表超过 30 秒没有推进会被拒绝；进度记录跨地址续签和
会话轮换保留，避免重新申请地址后把停滞列表再次当作健康源。

普通频道缓存最多保留 30 秒；BK 模式还会按上游目标分片时长收紧时效。
刷新失败时仅允许短时间使用仍在有效期内的缓存，过期后返回 `503` 和
`Retry-After`，不再用 `200` 返回陈旧列表。连续三次失败后每 30 秒重试；
恢复后自动回到正常刷新频率。即使上游持续返回 `200`，分片超过 30 秒没有
前进也会标记为异常。这个阈值针对当前短分片直播源，不适用于长分片点播。

`/diag` 显示每个频道的当前模式和 CDN 主机、最后成功时间、分片更新时间、
最近一次刷新耗时、累计上游限流次数、`worker`（是否有后台刷新任务）、
`fresh`（缓存是否仍有效）和最近错误。`/health` 仅检查进程能否响应，不代表
所有频道或客户端直连的 CDN 分片都可播放。

诊断页同时显示构建版本、BK/JCE 各自最近一次尝试结果和设备源频道错误；
`ok` 表示该来源最近一次尝试成功，空字符串表示尚无记录，不代表当前输出来源。
设备初始化失败会明确标注，并显示进程级冷却的下一次允许尝试时间。
最近一轮云注册的 `get`、`register-*`、`get-confirm` 会分别显示 HTTP 状态、
业务码、是否解析到 GUID，以及只含字段名和类型的响应结构。这些云注册记录不会输出
GUID、身份参数、Cookie 或原始响应值；BK/JCE 错误中的 URL 路径和查询参数会脱敏。
注册后的最终查询必须业务码成功且含可识别 GUID，不能用本地旧 GUID 掩盖失败。

长期运行的资源边界：每个频道最多一个刷新任务；JCE 分片缓存最多 60 个；
内置设备会话有效期为两小时、每 30 秒发送一次心跳。频道地址初始缓存一分钟，
播放列表持续推进时自动续期，避免正在播放的频道每分钟重新申请地址；会话或地址
轮换后，旧播放列表对应的媒体凭据还会保留两分钟，避免已经下发的分片突然失效。
单个模拟设备最多保留 6 路活跃高码率链接，5 分钟未访问才释放本地配额；这个
保守窗口避免本地过早释放、但上游仍计数，最终累计触发隐藏的 10 路上限。超过配额
的频道直接使用 BK/JCE，不会继续请求设备接口或反复注册新身份。
主程序日志写到标准错误，部署时应交给带容量限制的 systemd journal、容器日志
驱动或 logrotate 管理，避免把输出无限追加到单个文件。

上游鉴权、CDN 地址和协议可能变化，客户端也可能无法访问分片；这些不能由
本地缓存修复保证。故障时保留 `/diag`、对应时间的日志以及播放器报错，
区分列表获取失败与客户端直连 CDN 失败。

## 首播、切台与码率

所有频道默认优先使用 BK，BK 不可用时尝试 JCE；已知 JCE 不可用的频道跳过
JCE。BK/JCE 仍有有效列表时不会预热或尝试设备源，包括已有设备会话的情况。
只有 BK/JCE 都无有效列表时，支持设备协议的 CCTV/CGTN 频道才继续尝试设备源；
过期列表不算可用数据。设备会话初始化失败会触发进程级 15 秒、60 秒、120 秒
递增冷却，避免切台时每个频道重复等待同一次云注册失败。BK 地址发现请求全局串行且至少间隔 700 毫秒；JCE
回退在整个进程内最多并发两个请求，请求启动至少间隔 500 毫秒，避免播放器批量
探测频道时触发上游限流。处于 JCE 回退的频道每 30 秒尝试恢复 BK。

首次 BK 加载最多等待 60 秒（包含全局排队），为 64 路同时冷启动保留空间；
已播放频道的 BK 尝试限时 8 秒，JCE 尝试另有 12 秒预算。单次刷新及播放列表
请求最多等待 75 秒。JCE 先刷新当前源，再用最多 2 秒探测 BK，探测失败不影响
已获取的 JCE 列表。上游长时间拥塞仍可能超时并返回 `503`。

支持且允许尝试设备备用源的频道，在这 75 秒总预算内为设备回退预留 20 秒，
因此该观众最多等待 BK/JCE 55 秒；共享的 BK/JCE 后台刷新仍遵循自身预算。
设备回退不会再额外延长 HTTP 请求的总等待时间。

BK、JCE 和内置设备协议切换共用输出序号，并在切换处保留 discontinuity 边界；
CDN 候选若比当前进度落后会被拒绝。直播结束列表不会下发给播放器；JCE
停止推进会立即尝试 BK。内置设备协议失败按频道进行 15 秒、60 秒、120 秒
递增冷却，任一频道失败都不会禁用其他频道。设备 `live/v1/01` 的 HTTP 400
按链接配额/频道业务错误处理，不会销毁整个设备会话并触发云注册风暴；明确的
会话鉴权错误以及后续加密步骤的 400 才会轮换会话。

云设备 `get` 接口会用 HTTP 400 返回正常业务码 `result=2`（需要注册）；实现会先
解析业务码再决定是否调用 `register`。AppStart/直播请求与云注册/心跳/VDN 使用
独立 Cookie 会话，避免跨子域 Cookie 污染控制接口。

输出时间线还会检测 discontinuity 序号重置，以及重叠分片的主机、路径或
字节范围变化，必要时分配新的序号和解码边界；仅签名查询参数变化不触发切换。
BK 成功刷新按请求开始时间计算下一轮周期，避免网络耗时额外拉长刷新间隔。
JCE 重建当前只支持完整、未加密的 TS 分片；遇到需要 KEY、MAP、BYTERANGE
等元数据的格式会明确拒绝并尝试 BK，不会丢掉必要标签后输出损坏列表。

编码器重启导致 BK 序号归零时，旧 BK 时间线停滞超过 30 秒后，需要同一候选
在 60 秒内连续两次显示序号进度前进，才允许恢复；有明确旧时间戳的列表仍被
拒绝。BK 进度独立记录，不会被正常播放的 JCE 刷新掩盖。JCE 窗口完全断开时
会保留显式解码边界，即使边界已被输出窗口裁剪掉也会补齐。全部分片标记为
GAP 的列表不能作为健康源；包含可用分片的混合窗口仍可正常使用。

停掉后台任务的频道再次访问且缓存已过期时，首轮刷新重新使用冷启动排队预算，
不因曾经播放成功而缩短为 8 秒。同一 CDN 路径续签 URL 会保留重启确认记录，
但不会延长记录有效期，也不会跨 CDN 继承。

BK 取流会优先复用上次成功的 CDN。首选源超过 250 毫秒尚未完成
时，开始探测一个备用源；单频道最多同时拉取两个候选源，选出有效列表后取消并
回收其他请求。网络失败、列表停滞和竞争中明显较慢的地址冷却 10 秒。候选源及其
健康记录最多保留 16 个，签名地址更新时清理旧记录，避免长时间运行后累积。

仍能成功获取列表的缓存地址会继续使用，不再每隔五分钟先阻塞查询新地址。
缓存地址全部失败时才重新发现；新签名可以立即尝试，但不会清除已有的分片
停滞历史。切回缓存仍有效的频道直接返回列表，不等待上游请求。

对于上游返回的多码率列表，默认选择峰值带宽不超过 **6 Mbps** 的最高码率版本；
如果全部超过上限，选择最低码率版本。选择与列表顺序无关。可调整上限，例如：

```bash
./ysp-live-go -max-bandwidth 3000000
```

`-max-bandwidth 0` 选择最高码率。这是服务端固定选档策略，不是播放器自适应码率；
只对具有多个版本的 BK 播放列表生效，不会转码或限制单码率流的实际下载速度，
也不会改变内置设备协议的选档。

JCE 播放列表会保留上游的时间线切换标记，并在窗口滑动、标记移出窗口及重复
刷新时保持分片的 discontinuity sequence 稳定。

## 内置设备协议的网络行为

内置实现会生成模拟电视身份，调用央视频的 AppStart、云设备注册、心跳、直播
地址和 VDN 接口。设备身份以 `0600` 权限持久化；会话密钥只保存在进程内存，
媒体 URL 使用进程随机 HMAC 签名，不能被客户端伪造成任意代理请求。分片使用
唯一 pathname，兼容会错误忽略查询参数缓存键的电视播放器。Range 请求会透传，
单个媒体请求最长五分钟，下游单次写入最多等待 30 秒，观众取消或服务退出会
中断阻塞写入。全进程最多同时中继 64 个媒体请求，超额返回 `503` 和
`Retry-After`，释放容量后可重试。

设备列表中的 AES-128 密钥、MAP 初始化段和普通分片都通过签名中继获取，并
保留字节范围等标签；不支持的加密方式会明确拒绝并回退。输出时间线使用原始
媒体身份判断进度，因此签名、设备条目或访问服务的主机变化不会使同一分片
重新编号。只有最终选中返回的来源才会提交输出时间线。

启用默认设备协议即表示接受上述上游网络行为；可使用 `-device=false` 完全关闭。

## 项目结构

```text
cmd/ysp-live/
├── main.go          # 参数、启动和退出处理
├── server.go        # HTTP 路由和 M3U 输出

```
